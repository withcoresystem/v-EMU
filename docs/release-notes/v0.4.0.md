# v-EMU 0.4.0

v-EMU 0.4.0 is a **host-support narrowing release**. It adds no new VM, guest,
console, seamless or 3D features.

## Host support

Supported hosts:

| Host | Status |
|---|---|
| Fedora 45 | Primary, full feature; KDE Plasma, GNOME and COSMIC UI tested |
| AlmaLinux 10.3 | Primary, full feature |
| RHEL 10.3 | Primary, full feature |

AlmaLinux 9.9 remains an optional EL9 installation-test path through
`contrib/setup-el9.sh`; it is not a primary tier.

Removed from the main tree:

- Debian and Ubuntu hosts;
- openSUSE, SUSE and SLES hosts;
- Arch, CachyOS and Omarchy hosts.

The broad 0.3.1 release remains on the public `maint/0.3` branch with its old
host matrix. Guest OS support in the VM wizard and templates is unchanged.

## Installer

`setup.sh` is now a single dnf path for Fedora/RHEL-family. The Debian,
openSUSE/SUSE and Arch package-manager branches, Debian firmware path and
Debian-specific PySide6 pin are removed. `--precheck`, `--standard`, `--full`
and `--uninstall` keep their existing semantics.

`contrib/setup-arch.sh` is removed; the historical Arch note is archived.
`contrib/setup-el9.sh` and `contrib/setup-freerdp-el9.sh` remain for EL9
installation and seamless testing.

## Host code

`vemu` resolves `qemu:qemu` as the QEMU worker on supported hosts, with
`VEMU_QEMU_USER`/`VEMU_QEMU_GROUP` and active `/etc/libvirt/qemu.conf` values
still taking precedence. Debian/Arch auto-detection is removed.

AppArmor host detection was removed with the Debian/Ubuntu host path. The
Doctor and desktop UI now report SELinux only, and the Debian firmware fallback
under `/usr/share/OVMF/vemu` is gone. SELinux remains the supported security
layer on Fedora and RHEL-family hosts.

## Validation

Clean virtual machines on the three primary hosts ran `setup.sh --precheck`
and `setup.sh --standard` on 2026-11-25. All finished with v-EMU 0.4.0, an
active `vemud` and a passing `vemu doctor`; Alma/RHEL only reported the
expected optional cross-architecture TCG warnings.

RHEL 10.3 (QEMU 10.1.0, libvirt 12.5.0, FreeRDP 3.32.2) was exercised
beyond installation:

- storage registration, NAT network, VM create/start, console, stats,
  screenshot and snapshot;
- Image Builder 79.0.0 with osbuild 191 built the `rhel-10.3` GNOME qcow2
  (1.9 GiB) in 26m47s after a subscription-aware preflight;
- `vemu seamless prepare/status` and a Command Prompt RAIL test with FreeRDP
  3.32.2 on KDE Plasma Wayland through Xwayland;
- the Qt desktop UI launched under the headless KWin session.

The full desktop UI matrix is covered on Fedora 45, which has KDE Plasma,
GNOME and COSMIC sessions installed and exercised.

The headless RHEL check supplied a display with a KWin virtual session
(`kwin_wayland --virtual --xwayland`); normal use still requires a logged-in
desktop session as described in [`WINDOWS-SEAMLESS.md`](../WINDOWS-SEAMLESS.md).

Fedora 45 is the only primary host whose default repositories ship the
aarch64/riscv64 TCG packages, so `--full` is Fedora-only by default.
AlmaLinux and RHEL 10.3 remain `--standard` unless those packages are added
from another source.

## Upgrade notes

- Fedora 45 and Alma/RHEL 10.3 users upgrade with the normal `.run` or
  `./setup.sh --standard` path.
- Debian, Ubuntu, openSUSE/SUSE and Arch users should stay on the 0.3.1 broad
  release (`maint/0.3`). Do not expect further host fixes in 0.4.x.
- VMs, templates, storage and guest support are not converted or removed by
  this release.
- The public `v0.3.1` tag and artifacts remain available.

## Explicitly unchanged

- VM lifecycle, storage chains, snapshots, templates and cloning.
- Networks and lab workflows.
- Windows seamless mode and the experimental CLI-only 3D helper.
- Image Builder guest catalog; Image Builder host support remains
  Fedora/RHEL-family.

## Next

0.5.0 is planned as a maintenance-and-polish release: bug fixes, UI/UX
improvements and CLI shell autocomplete for the `vemu` command tree. It will
not re-open the removed host families; those users stay on 0.3.1.
