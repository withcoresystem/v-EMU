# v-EMU 0.2.0

**External VNC, local Image Builder and a clearer snapshot chain.**

v-EMU 0.2.0 keeps the 0.1.0 lab workflow and adds the two 0.2.0 features:
an external TigerVNC console and native Image Builder orchestration for qcow2
and installer ISOs. It also fixes the snapshot-layer semantics that made
reverting from a labelled layer ambiguous.

## Highlights

- **External VNC viewer:** a fixed, loopback-only TigerVNC command with
  per-VM duplicate protection and a viewer log; embedded noVNC stays available.
- **Image Builder:** qcow2 and installer ISO jobs from native `image-builder`
  blueprints, with rootless manifest preflight, package/repo checks, one build
  at a time, cancel/log/hide and explicit root consent.
- **OSBuild catalog:** browse the distro/arch/image-type combinations reported
  by `image-builder list`, with filters and asynchronous loading. The default
  view now hides cloud/edge/container types that v-EMU does not use.
- **Package lookup and metadata cache:** search packages and groups for a
  target distro with comma-separated terms, show hidden package groups, copy
  names/rows from the context menu, validate group names and reuse a local
  SQLite cache. Lookup is read-only; builds still run the full manifest
  preflight.
- **Branded installer ISO:** Anaconda sidebar/header/logo, GRUB entries,
  a Plymouth boot theme for the installed system, and an optional fullscreen
  first-boot TUI for USB or HTTP(S) payloads.
- **Automatic first-boot payload:** optional **Script name**/**Script URL** in
  the ISO wizard skip the menu, retry automatically, restart on success and
  fall back to the menu on failure.
- **Snapshot model 2:** a snapshot freezes the current layer and continues on a
  new **Current** layer; revert discards the current layer instead of writing
  into a snapshot. New chains use model 2; legacy chains keep the old layout.
- **Clone flow:** contextual General/Linux/Windows tabs, a faster offline
  identity reset and an explicit opt-out for cloud-init-style identity.
- **UI fixes:** Image Builder always opens on Images; build jobs keep only the
  final artifact and `build.log`; the main window remembers a user-resized
  size and maximized state.
- **Passthrough guard:** VMs with PCI/mediated/SCSI/SR-IOV passthrough are
  detected as read-only **External (VFIO)**, so v-EMU never rewrites, clones
  or migrates host devices. USB passthrough stays fully managed.

## Upgrade notes

- Existing snapshot chains without `snapshot_model` retain the legacy layout.
  Recreate or flatten a chain to use the Current-layer model.
- Re-run `./setup.sh --standard` (or install the new `.run`) to update the
  system daemon and app copy. Log out/in if group membership changed.
- First-boot payloads run as root. Use HTTPS and a trusted server; Debian,
  Ubuntu and openSUSE are not Image Builder hosts.

## Validation

The 0.2.0 tree passes 721 automated tests (43 subtests). The full AlmaLinux 10.2
KDE ISO cycle (build, install, branded boot and first-boot TUI) was exercised
with both USB and HTTP(S) payloads; Fedora KDE and RHEL-like ISO builds pass
preflight.

The release-candidate artifact `vemu-0.2.0-x86_64.run` (SHA256
`0531abcbeb937b04ab797148148266d18a409e7765ec3260a39f4910ada762ea`) was
installed over an existing 0.1.0 installation on the development guests:

| Guest | Upgrade / check | Result |
| --- | --- | --- |
| Omarchy (Arch family) | `contrib/setup-arch.sh` run twice over the existing source install | PASS: both runs exit 0; `vemu 0.2.0`, `vemud` active/enabled, daemon and source files match |
| Debian 13 | `.run --standard` over 0.1.0 | PASS: `vemu 0.2.0`, `vemud` active; Image Builder shows **unsupported host** and “only supports Fedora and RHEL-family hosts”; New build/Recheck disabled |
| openSUSE Leap 16.1 | `.run --standard` over 0.1.0 | PASS: same Image Builder block; CirrOS cloud image imported as a template, clone started, VNC console opened with TigerVNC, then stopped, restarted and deleted |
| Fedora 45 Workstation | `.run --standard` over 0.1.0 | PASS: Image Builder ready; `fedora-gnome` blueprint built a 1.8 GB qcow2 in ~53 s; UI screenshots render under COSMIC, Plasma and GNOME; deleting a root-owned qcow2 now goes through vemud and succeeds |

TigerVNC is a documented external-viewer prerequisite and is not installed by
`setup.sh`; the Leap test installed `tigervnc` explicitly and then verified
`vemu console <vm> --open` with the fixed viewer flags.

The experimental Arch-family installer in `contrib/` is not part of the
`.run` artifact; it supports `--full` for aarch64/riscv64 TCG. It was validated
on CachyOS and Omarchy/Hyprland, and an Alpine aarch64 UEFI cloud image booted
to a login prompt using the v-EMU custom firmware. See
[`docs/ARCH-EXPERIMENTAL.md`](../ARCH-EXPERIMENTAL.md).

The VFIO read-only guard is covered by XML fixtures for PCI, mediated,
SCSI-host and SR-IOV devices. The validation host had no spare PCIe device, so
no live passthrough VM was booted; VFIO remains a manual, non-goal use case.
