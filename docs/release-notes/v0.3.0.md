# v-EMU 0.3.0

**The final broad host release: Windows seamless mode, chain compaction and a
narrower primary host tier.**

v-EMU 0.3.0 is the last release that maintains the broad host matrix. It keeps
the 0.2.0 lab workflow and adds the optional Windows seamless path, active
snapshot-chain compaction and the final experimental Windows 3D helper. The
next tree, **vEMU-RHEL**, narrows host support to Fedora/RHEL-family while
keeping the VM wizard and guest scope unchanged.

## Highlights

- **Windows seamless mode:** prepare a Windows 10/11 Pro/Enterprise guest for
  RemoteApp/RAIL publishing, add and test programs, pause without losing the
  guest setup, or remove and restore the pre-seamless checkpoint. Seamless is
  optional and requires FreeRDP >= 3.26.
- **Chain compaction:** merge the active snapshot branch into the first layer
  and reclaim host space. Non-active branches are discarded; clone/export them
  first if they must be kept. The UI runs compaction in a worker thread with a
  non-freezing running indicator.
- **Host-state cleanup:** deleting a VM now removes host shortcuts/icons,
  supervisor state and keyring entries; **Delete VM only** keeps recoverable
  chain/XML/SSH state, while **Delete VM and disks** purges it.
- **Doctor host security:** the Doctor page reports `seccomp_sandbox`, remaining
  experimental 3D state and the qemu.conf backup. A guarded restore action is
  available after all 3D VMs are reverted or deleted.
- **Experimental Windows 3D (CLI only):** `vemu experimental 3d` remains
  unsupported, SPICE-only and test-signed; it is not a path for RDP, RemoteApp
  or seamless.
- **Host tiers:** Fedora 45, AlmaLinux 10.3 and RHEL 10.3 are the primary,
  fully tested tier. Debian 13.x, Ubuntu 26.04, openSUSE Leap 16.1 and
  Arch/CachyOS/Omarchy are secondary/experimental tiers with documented
  caveats.

## Host support

Primary hosts receive full feature validation and release-blocking fixes.
Secondary hosts are tested but may need host-specific workarounds for package
splits, FreeRDP versions, Secure Boot/OVMF or rolling-release changes. The
detailed matrix is in [`../../MANUAL.md#host-support`](../../MANUAL.md#host-support).

Image Builder remains Fedora/RHEL-family only. Arch-family hosts keep the
separate `contrib/setup-arch.sh` installer and do not include Image Builder.

## Validation

The 0.3.0 tree passes **990 automated tests** (47 subtests). The final host
runs included:

- Fedora/RHEL-family primary coverage from the 0.3.0 development cycle,
  including KDE, GNOME and COSMIC UI checks.
- CachyOS `contrib/setup-arch.sh --full` install/upgrade, a Debian cloud image
  with nested KVM, snapshot/revert and delete, plus Windows import,
  seamless prepare, Notepad RAIL, pause and pre-seamless restore.
- Ubuntu 26.04 `setup.sh --full` install/upgrade, Debian cloud image with DHCP,
  snapshot/revert and delete, plus Windows import and seamless prepare,
  Notepad RAIL, pause and pre-seamless restore.
- Debian 13 and openSUSE Leap 16.1 evidence from the earlier 0.3.0 cycle.

Known validation caveats:

- Ubuntu 26.04/QEMU 10.2 required Secure Boot off for the imported Windows 11
  template used in the seamless test; the same template boots with Secure Boot
  on the primary Fedora host.
- The CachyOS cloud run used a static cloud-init address; DHCP was not
  confirmed on that host. Ubuntu's libvirt default network did provide DHCP.
- A headless Edge RAIL one-shot failed on CachyOS; Notepad RAIL passed on both
  CachyOS and Ubuntu. Treat that as an app-specific Edge result, not a
  converter failure.

## Upgrade notes

- Re-run `./setup.sh --standard` or `--full` to update the daemon, CLI/UI and
  firmware. Arch-family hosts use `./contrib/setup-arch.sh --full`.
- Shared seamless state now lives under `/var/lib/vemu/seamless` with
  `/var/lib/vemu/experimental3d` for 3D. The installers prepare both
  directories; do not point the root daemon at a user state directory.
- Seamless needs `xfreerdp`/`xfreerdp3` (FreeRDP >= 3.26) and Python keyring
  support for saved passwords. `setup.sh` installs `freerdp3-x11` and
  `python3-keyring` where the distribution provides them.
- Ubuntu 26.04 split riscv64 QEMU into `qemu-system-riscv`; 0.3.0 accepts that
  package for `--full`.
- 0.3.0 is the final broad release. Repository work after this point is the
  host-only vEMU-RHEL fork for Fedora/RHEL-family hosts.

## Non-goals unchanged

v-EMU remains a single-host, local, lab-first tool. There is no cluster/HA,
live migration, web multi-user UI, supported commercial vGPU/GPU partitioning,
macOS guest support or general 3D/GL promise. See
[`../../MANUAL.md#host-support`](../../MANUAL.md#host-support) and
[`../../README.md`](../../README.md).
